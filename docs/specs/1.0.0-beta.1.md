# FrameTrail 1.0.0-beta.1 — REASONS

Status: implementation, pending CI and device acceptance. Application version: 1.0.0, build 1. Release: 1.0.0-beta.1.

## Requirements

R1. Search a large external catalog of movies and shows. A fresh install works with TVmaze and Wikidata without developer credentials; a personal TMDB API read token enables TMDB search and authorization. Wikidata film results require an explicit film or feature-film instance claim, rather than matching words in a description. Catalog coverage is provider-dependent.

R2. Save a library, explicit completed episode IDs, film completion, discussions, ratings and personal reflections. Guest and authenticated accounts have isolated libraries. The user may export/import their own library.

R3. Generate grounded responses locally with Apple's system model. Check model and requested-language availability before every response. Never route a discussion to cloud inference. For Russian, prefer native model support; otherwise use Apple's on-device Translation framework to translate the question and permitted source texts into English and the answer back into Russian. Check both translation directions and require installed language resources before inference. An explicit Settings action requests system consent for missing language downloads. Default to Russian for a Russian system language, with English always selectable.

R4. Before generation, enforce title and episode boundaries in deterministic code. Movie source material is available only after completion. Series summaries and imported facts are available only for completed episode IDs. Finishing one title does not unlock a sequel. Rewinding progress clears previous discussions because their text may reveal later events.

R5. Explain source coverage and make evidence inspectable without invoking a model. Do not present an overview as a complete screenplay. Do not promise zero spoilers from free-form generation: pretrained knowledge can leak. Label interpretation separately from sourced facts.

R6. After completion offer an ending discussion, brief recap, motivations, open questions, and a saved personal reflection. Ratings and user opinions remain editable.

R7. Import UTF-8 text or SRT/WebVTT as user-provided sources, scoped to a title and, for shows, a specific episode. Entire-episode imports are unavailable until that episode is completed. This beta uses completed episodes rather than an unsupported scene-level safety claim.

R8. Keep the binary compact: no bundled model weights, analytics or third-party runtime SDKs. Bound network bodies, imported content and conversations. Download only selected titles; expose local storage and remove cached source material separately from user records. Optional Apple translation language packs are shared system assets downloaded with system consent; their storage is additional to the app and their size depends on the installed system resources.

R9. Primary FrameTrail accounts use Supabase email/password authentication, verified email and refreshable sessions in Keychain. Each account owns an isolated offline library. Synchronize title metadata, viewing progress and personal reflections/ratings between devices; keep source texts, episode descriptions and discussions on the device. Use server revisions and compare-and-swap writes, retain deletion tombstones and ask the user to resolve concurrent changes. Failed or interrupted sync never erases offline edits. Guest data remains local until explicitly imported into an account. Account deletion requires explicit confirmation and deletes the owner's cloud records. Public signup and password recovery require configured SMTP; do not disable email verification to bypass provider restrictions.

R13. TMDB is an optional secondary catalog/watchlist connection, independent of the primary FrameTrail account. Its real authorization uses request-token approval in the provider browser and explicit completion in the app; the app never receives the TMDB password. Session and application tokens live in Keychain and are excluded from export. Explicit read-only watchlist import fetches up to ten pages each of movies and shows (up to 400 titles), adding missing titles without replacing existing records. Connecting or disconnecting TMDB never switches the primary library.

R10. Publish open source under MIT with Conventional Commits, SemVer prereleases and a reproducible unsigned IPA that AltStore re-signs. CI must pass before tag publication; the IPA is not a pre-signed enterprise download.

R11. Maintain Russian primary README and a complete English counterpart with reciprocal language links, real installation and account steps, source/privacy terms and the same beta limitations. Present repository identity with the original app icon and consistent badges for live CI, published SemVer release including prereleases, release asset downloads, stars, license and minimum iOS. All counters must derive from public GitHub metadata, with asset downloads distinguished from installations. Add no visitor tracking, invented popularity or fabricated screenshots.

R12. Show compact viewing statistics in the journal: saved titles, completed titles, explicitly watched episodes, reflections and movie/show counts. Average and distribution of overall ratings use the latest whole-title reflection per title, so repeated journal entries never weight one title twice. Calculate episode ratings separately from the latest reflection for each title/episode pair. An explicitly unrated latest record removes that scope from averages. Empty libraries show zero counts and no invented average. Derive statistics from the active account's library; add no analytics, persisted counters, inferred watch hours or completion dates.

## Entities

R14. Complete the primary viewing flow with season navigation for large episode lists, direct discussion-to-reflection actions and native sharing. Saving a reflection accepts any nonempty summary, liked detail, question or rating. Confirm destructive conversation clearing and reflection deletion. Reset navigation when switching the primary account. TMDB watchlist imports commit all new titles atomically, preserving existing records and surfacing failed writes. Cancelled authorization cannot later restore credentials; closing the provider browser attempts completion and retains a manual retry when approval is incomplete. Signed-in FrameTrail accounts can change their password.

R15. Support 1–10 ratings and liked/disliked impressions for a whole movie/show and for individual watched episodes. Movies require completion; a series can be reviewed after at least one episode or completion. Episode reviews identify the stable episode plus season/number and remain understandable after cache removal. Opening the rating action edits the latest record for that scope; a new journal entry inherits its current rating unless the viewer clears it. Optional Apple on-device guided generation produces exactly two fields: one question about what the viewer liked and one about what they disliked, adapting to the score, scope, allowed sources and supplied impressions. Episode questions receive only that episode's permitted material; missing sources permit subjective questions, never invented plot claims. Save the user's answers as personal impressions, not story evidence. If the model/language is unavailable, manual reviews still work. Cancel/discard generated questions when account or viewing boundary changes. Synchronize these reviews through the existing reflection projection; old archives without the new optional fields remain importable. Bound cloud title records at 512 KiB and paginate three at a time within the 2 MiB response limit.

MediaTitle identifies provider, kind, title metadata and source. Episode has a stable provider identifier, order, summary and source. WatchProgress stores completed identifiers and title completion. StoryFact records title/episode scope, category and provenance. GroundedContext is a bounded selection of allowed evidence. ChatTurn is a bounded local discussion record. Reflection preserves a user's review, likes, questions and optional 1–10 rating. LibraryEntry groups records for one title. AuthAccount is a provider identity, never a password container.

## Approach

Use SwiftUI and Observation for presentation, a Foundation-only Swift package for domain and three-way synchronization rules, URLSession actors for remote data, Foundation Models for local generation, Keychain for tokens and atomic protected JSON for small per-account collections and synchronization baselines. Supabase supplies authentication and PostgreSQL storage with owner-only row-level security. No runtime backend SDK or general-purpose dependency injection framework is needed. Only public project configuration is bundled; privileged credentials stay on the backend.

Keep source acquisition distinct from inference. Generate a fresh evidence-bounded session per question, with prior questions for conversational focus; never reuse an assistant answer as an authoritative source. Missing material results in an explicit coverage message. Use an English evidence envelope when English generation is selected; source-language availability is handled by the system model.

## Structure

- Packages/FrameTrailCore: domain values, spoiler-safe retrieval, subtitle parser; no UI, networking, persistence or model dependency.
- FrameTrail/Services: typed provider adapters, bounded HTTP, provider authorization, Keychain, Wikipedia plot acquisition and the on-device model boundary.
- FrameTrail/Persistence: account-isolated application records, import validation, atomic writes and cache removal.
- FrameTrail/AppModel.swift: application composition and current account/settings.
- FrameTrail/Views: feature screens and user interactions. Views delegate scope decisions to the domain layer and writes to the store.
- FrameTrailTests, FrameTrailUITests: service/persistence interactions and installed-app user flows.
- scripts, .github/workflows: validation, Xcode project generation, testing, IPA packaging and release.

## Operations

O8 Compile impressions: questions, answers and notes are optional; a viewer may save only a score or only their own text. For a series, select the latest personal reflection per watched episode. Build bounded 5,000-character packets, including at most 180 characters from each notes field and disclosing shortening. Generate local intermediate summaries and merge them in pairs until one retrospective remains. Each generation call has bounded context; report stages and allow cancellation. The prompt treats all notes as untrusted personal opinions and prohibits adding plot events or preferences. Let the viewer edit/share the result and explicitly save it as a whole-title journal reflection, inheriting their current overall rating. Do not mix episode ratings into whole-title rating statistics.

O1 Search: debounce and cancel outdated queries; fetch provider results; map external optional values at the boundary; show errors and provenance. Without a TMDB token, search TVmaze for shows and Wikidata for at most 15 candidate items, then fetch their labels, descriptions and claims. Include only candidates with P31 film Q11424 or feature film Q24869; preserve search order, optional P577 release year and source links, with no film artwork. Use Russian search for Cyrillic queries and English otherwise. Never erase stored records on a failed request.

O2 Track: load episodes, mark a single episode or all through a selected episode, persist atomically. On progress reduction clear the affected title's chat. Unwatched episode names/descriptions are hidden unless deliberately revealed.

O3 Discuss: select title, inspect coverage and check model/language availability. When Russian needs the translation path, translate the original question locally into English before evidence retrieval. Build allowed facts, translate only the selected source text and recent user questions, preserving source identifiers, URLs and viewing boundaries outside translation; run a fresh English model session and locally translate the answer into Russian. Display and save the original user question and the final answer. If scope, language or account changes during translation or generation, discard the pending response. Missing language resources require preparation in Settings, with no cloud fallback.

O4 Reflect: finish a title, optionally acquire its plot from the selected Wikipedia article, generate or write a personal summary, add likes/questions/rating and save. Show source links and distinguish the user's opinion from externally sourced facts.

O5 Authorize: sign in to FrameTrail with verified email/password, restore the session from Keychain and activate that user's cache. Synchronize after local changes and on foreground, with a manual retry and visible status/conflicts. Compare local, remote and saved baseline snapshots before applying changes. Apply a received cloud record while preserving local source material; a progress reduction clears the affected discussion. Store library changes and baseline atomically. A stale server revision produces a conflict rather than an overwrite. Logout retains the isolated offline cache but activates the guest library and clears credentials. Separately configure a TMDB read token, approve its provider authorization and import its watchlist. Validate replacement tokens before changing saved credentials. TMDB logout/token replacement must not switch the FrameTrail account.

O6 Import/export: reject oversized, unsupported or malformed files before mutation; validate URL schemes, IDs and value limits; merge valid library exports by most recent title record. Source imports are explicitly marked user-provided. Export contains no session tokens.

O7 Release: implement and stabilize each version in a retained release/<major>.<minor>.<patch> branch. Run source/metadata validation, package tests, service/persistence/UI tests, simulator and device builds on that branch. Package Payload/FrameTrail.app, enforce a 40 MiB app and IPA ceiling, generate SHA-256, publish the prerelease on an exact matching tag from the release branch. Verify the published assets and checks, then merge the release branch into main through a pull request. Never merge unfinished release work into main before these checks.

## Norms

R17. Optional review questions support multi-select prepared answers plus independent free text and explicit skip. Apple guided generation selects only passage IDs and a closed aspect enum from at most twelve candidates extracted from the permitted context. Do not display free model-generated plot descriptions as options. Resolve returned IDs against the original candidate map; reject invented IDs. Compose each option from a fixed aspect label and an exact allowed source excerpt, optionally localized with Apple Translation while preserving its original quote and provenance. For an episode, candidates must come only from that explicitly watched episode even if later episodes are already watched. If there is no permitted material, allow manual notes and scores rather than inventing episode-specific answers. Persist selected answers separately from custom notes, preserving multi-selection when editing, export/import and sync. Include their text in retrospective compilation. Refresh search/featured data immediately when TMDB configuration changes without applying stale requests.

Prefer meaningful types and stable identifiers to ad-hoc dictionaries. Use external optional fields only where the API permits absence. Keep mutation on the main actor and remote work in actors. Treat imported text as source data rather than instructions. Use accessible native controls, Dynamic Type, VoiceOver labels and visible loading/error/empty states. Keep Russian product copy separate from English model instructions. Preserve source attribution.

Use Conventional Commits. Keep a single semantic VERSION source consistent with bundle metadata. Public documents describe shipped behavior and limitations. Keep Russian and English README behavior, setup and limitation sections aligned. Every behavioral change updates this canvas before code; internal restructuring updates the architecture map after review.
