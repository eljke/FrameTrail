# FrameTrail 1.3.0-beta.1

Release contract for #15 and #4, with the cloud metadata correction tracked in #16. App 1.3.0, build 4, iOS 26+.

## Language and names

- Interface, assistant output and source translation are independent preferences. Catalog language follows the interface. Machine source translation is off by default and can be requested per fragment
- Check model language support at runtime. Unsupported Russian input is translated locally even when English output is selected
- iOS 26.4+ uses attributed translation with protected name and reference ranges. Earlier systems retain validated placeholders. Protected names must survive with the correct occurrence counts; a failed output translation returns the original generated text
- Confirmed per-title spellings override recognized originals. Unknown recognized names remain unchanged. Cyrillic names and abbreviations are eligible for recognition; uncertain name detection and inflection remain device acceptance concerns
- Translation never overwrites stored source text or user notes. Automatic source translation cannot override the chosen answer language

## Evening picks

- Interpret explicit type and maximum runtime into a bounded brief; manual controls take precedence. Show the resulting hard conditions
- TMDB candidates retain the existing 7/10, 300 movie votes and 150 series votes gates. Discover and favorite-title recommendations supply paginated candidates
- With a time limit, verify detail metadata for at most sixteen ranked candidates. Missing or zero runtime is ineligible. For shows the metadata describes episode duration, not total series length
- Subjective wishes are handled by the local model, not guaranteed content filters. No uncalibrated compatibility percentages
- A new batch advances the page without repeating shown identifiers. Editing conditions starts a new page sequence while retaining the session's shown identifiers. Do not relax conditions silently
- A request or general catalog quality supports cold start; written reviews are not mandatory. Saved-watchlist mode fetches twelve TMDB titles per page
- Model selections must resolve to supplied candidate IDs and valid supporting review/request IDs. Per-title review spellings stay scoped to their source title
- Hidden recommendations persist per account and synchronize. Restoration keeps pre-existing watchlist records and notes; discovery-only hidden records can be removed without adding them to the watchlist

## Characters and personal memory

- Character extraction uses an already restricted story context. The model selects supplied name/source identifiers; accepted cards require the name inside an exact original excerpt
- Co-occurrence is labeled as shared source material, not a confirmed relationship. Explanations use the existing cited-answer pipeline
- Series Pulse opens character cards at its selected watched checkpoint. A rewind excludes later episodes even if those episodes were previously watched
- Diary retrieval chooses the latest eligible review per scope before dropping cleared records. Search is literal word matching, bounded to twenty-four relevant records; it is not an exhaustive semantic index
- Local transcription records at most ninety seconds. Audio is temporary, never synchronized, and discarded after transcription or closing. Unsupported language and device states retain manual text entry
- Impression organization selects exact original sentences by identifier. No rewritten opinion is silently applied. The original note stays intact
- Retrospectives can select one season, display actual episode ratings and save a personal season summary. Missing scores are not zero; source edits and progress changes invalidate generated results

## Storage and delivery

No bundled model weights, extra runtime dependency, server generation or local catalog copy. Public recommendation metadata stays in at most four memory batches for ten minutes. Image cache retains its existing 16 MiB disk and 8 MiB memory budgets; account archives remain capped at 10 MiB. System speech and translation assets are managed by iOS and may consume additional device storage.

Cloud migrations explicitly allow only known optional metadata and validate types. Existing verified-owner checks, revision concurrency and owner RLS remain. SQL acceptance runs in a rolled-back transaction.

Acceptance requires core and native regression tests, main-route UI checks in RU/EN, device build, IPA size and checksum inspection, and verification of the published artifact before merging main. Semantic model quality, real microphone transcription, proper-name translation and sideload installation require separate physical-device acceptance; simulator checks do not establish those results.
